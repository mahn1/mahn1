# Инструкция для ИИ-агента: производство и рендер на компьютере пользователя

Эта инструкция предназначена агенту, который может читать и изменять локальные файлы и запускать команды на компьютере пользователя. Работай в локальной копии проекта. Не говори, что файл создан, пока не проверил его. Не отправляй код и данные в интернет без согласия пользователя; исключение — пользователь согласился на озвучку через FreeTTS, которая отправляет текст сцен на api.freetts.ru. Не публикуй ролик, не пушь изменения и не удаляй пользовательские файлы без разрешения.

## 1. Задача и сценарий

Прочитай `AGENTS.md`, `README.md`, `story.example.json`, `render.mjs` и `public/scene.js`. Узнай тему, главный тезис и желаемый тон; не задавай повторно вопросы, на которые уже ответили. Прочее выбери самостоятельно, сообщив важные допущения. Язык — русский, диктор — Егор Тихонов, формат 1080×1920, 30 кадров/с, до 60 секунд. Напиши короткий сценарий, создай JSON с массивом сцен и адаптируй Three.js-сцену под историю: окружение, 2.5D, действия персонажа, эмоции и смену планов. Шаблон — не законченный мультфильм. Избегай перегрузки текстом и проверяй факты.

## 2. Проверь среду

Открой терминал в папке проекта (где лежат `render.mjs` и `tts.py`). Определи ОС и проверь доступность программ:

```sh
node --version
npm --version
ffmpeg -version
ffprobe -version
```

На Windows проверь `python --version`, на macOS/Linux — `python3 --version`. Требуются Node.js 20+, Python 3.10+, ffmpeg и ffprobe; у пользователя они уже установлены, поэтому сначала проверяй, а не переустанавливай. Если команда не найдена, выясни реальный путь или попроси пользователя помочь настроить PATH. Не выполняй установку системных компонентов с повышенными правами без согласия.

Если зависимости проекта или Chromium отсутствуют, установи из папки проекта с разрешения пользователя:

```sh
npm ci
npx playwright install chromium
```

Для Python выполни `python -m pip install -r requirements.txt` на Windows или `python3 -m pip install -r requirements.txt` на macOS/Linux. При необходимости используй существующее виртуальное окружение. Рендер на Windows запускает `python`, на macOS/Linux — `python3`; если нужный интерпретатор находится под другим именем, задай переменную окружения `PYTHON` равной пути к нему. Например, в PowerShell: `$env:PYTHON = 'C:\путь\к\python.exe'`. На macOS/Linux: `export PYTHON='/путь/к/python'`.

## 3. Проверь озвучку и подготовь ролик

Уточни, согласен ли пользователь отправить текст в FreeTTS, если ранее это не было согласовано. Голос указан по имени: номер в списке API может меняться. Проверь API и короткую озвучку:

```sh
# Windows: замени python3 на python
python3 tts.py --list
python3 tts.py --voice "Егор Тихонов" --text "Это проверка голоса." --output .render/voice-test.mp3
ffprobe -v error -show_entries format=duration -of default=noprint_wrappers=1:nokey=1 .render/voice-test.mp3
```

Если FreeTTS недоступен или голос не работает, сообщи точную ошибку; не подменяй голос молча. Можно использовать заранее подготовленную озвучку: в каждой сцене JSON добавь `"audio": "путь/к/файлу.mp3"`, путь относительно папки JSON. Текст сцены остаётся нужен для субтитра. Внешняя озвучка должна соответствовать тексту сцены; убедись в этом.

Проверь, что визуальная логика использует данные сцен, а не только пример морского фона. В `window.drawFrame(scene, seconds)` время отсчитывается с начала каждой сцены. Текущий шаблон рисует субтитры целыми фразами, не по словам; для караоке потребуется отдельная синхронизация слов с аудио. При необходимости улучши рендерер, сохраняя совместимость со сценарием и обеспечивая синхронизацию.

## 4. Рендер и проверка

После создания сценария, например `story.json`, выполни:

```sh
npm run render -- story.json output.mp4
ffprobe -v error -show_entries format=duration:stream=codec_name,codec_type,width,height,r_frame_rate -of json output.mp4
```

Убедись, что в файле есть видео H.264 1080×1920 при 30 fps, аудио AAC и длительность не превышает 60 секунд; открой или прослушай результат и по возможности посмотри кадры, чтобы проверить речь, субтитры, границы кадра и смену сцен. Если слишком длинно, сократи сценарий и повтори рендер. При ошибке устрани её и запусти повторно, не утверждая успех до проверки.

`.render/frames` при запуске удаляется и создаётся заново; не храни там пользовательские материалы. Кадры требуют много места, а покадровый рендер может занять много времени. Вывод `output.mp4` перезаписывается без подтверждения — выбери новый путь, если файл уже существует и пользователь не согласился на перезапись. `.render/` и MP4 исключены из git. Назови пользователю полный локальный путь к результату, длительность и оставшиеся ограничения.
