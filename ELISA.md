# Elisa Viora 1.0

Elisa Viora 1.0 — настольный ИИ-оркестратор задач и инструментов на C# (Windows Forms + WebView2) с моделями OpenRouter, NVIDIA Build и Arena API. Главный агент может делегировать подзадачи отдельным агентам исследования, реализации и проверки, а затем объединять их результаты.

## Настройка и использование

1. Запустите `Elisa.exe` и откройте **Настройки → Модели**. Выберите основной провайдер OpenRouter, NVIDIA Build или Arena API, введите его API-ключ и ID модели с поддержкой tool calling. Для NVIDIA указан пример `deepseek-ai/deepseek-v4.1-flash`; проверьте его наличие и условия на [NVIDIA Build](https://build.nvidia.com/). `openrouter/free` выбирает бесплатную модель автоматически. У каждого сервиса свои лимиты, цены и правила обработки данных; платные модели расходуют баланс. Оставьте поле ключа пустым, чтобы сохранить прежний. Старый ключ и модель OpenRouter остаются доступны после обновления.
2. Во вкладке **Рабочие области** добавьте одну или несколько папок. Без них файловые инструменты не смогут работать с файлами. В обычном режиме агент автоматически читает и перезаписывает текстовые UTF-8 файлы, создаёт папки и просматривает список файлов в выбранных областях; отдельные подтверждения не показываются.
3. При необходимости можно включить **Полный доступ к Windows**. Тогда агент получает ещё PowerShell и Python **без подтверждений и без ограничений рабочими областями** — с правами, с которыми запущена Elisa. Он может изменять или удалять любые доступные файлы, выполнять программы и обращаться в сеть. Права администратора автоматически не выдаются; не запускайте приложение администратором без необходимости.
4. На вкладке **Система** нажмите «Добавить Elisa в PATH». Приложение добавит текущую папку в пользовательский PATH; перезапустите терминал и запустите `Elisa`. Если переместите приложение, добавьте новую папку в PATH снова и удалите устаревшую через настройки среды Windows. PATH не регулирует права или подтверждения.

## Провайдеры и Python

- Настройка «Модели агентов» позволяет отдельно задать для ролей исследования, реализации, проверки и общих задач OpenRouter, NVIDIA Build или Arena API и ID модели. Пустой ID использует модель этого провайдера по умолчанию; «Как основной» наследует выбранного главного провайдера. Оркестратор решает, когда делегировать. Независимые задачи исследования и проверки могут выполняться параллельно; автоматического переключения при ошибках и автоматического выбора бесплатного тарифа нет.
- Основной агент отправляет историю текущего чата выбранному провайдеру; дочерний получает текст делегированной задачи и результаты собственных инструментов. При переходе на другого провайдера/модель сведения конкретного провайдера из старой истории убираются, но история и содержимое вложений передаются новому провайдеру. Возможности инструментов и изображений зависят от модели. NVIDIA Build и Arena API в Elisa поддерживают текст и изображения (если модель поддерживает их), но не PDF/бинарные вложения: начните новый чат без них или используйте OpenRouter. API-запрос к каждому сервису использует только его ключ; ключи сохраняются вместе с историей через DPAPI Windows. В полном режиме код агента имеет права текущего пользователя и не является защитой от утечки секретов.
- **Arena API:** в [кабинете Arena](https://platform.arena.ai/) нужен отдельный API-ключ и workspace с доступом сторонних API-клиентов. В Elisa выберите Arena API и введите ключ в настройках приложения (не в чат); пример ID — `coding-router-preview`. Запросы идут на `https://api.arena.ai/v1/chat/completions` в OpenAI-совместимом формате. Проверьте доступные модели и разрешения в своём workspace. Coding Router выбирает модель для запроса; совпадение с моделью этого чата не гарантировано. При ограничении доступа к сторонним клиентам возможен HTTP 403. Цены, квоты и обработку данных проверяйте в Arena; подписка или доступ к чату не гарантируют доступ к API. Доступность потокового режима, изображений и инструментов зависит от сервиса и модели. API моделей не предоставляет автоматически инструменты Arena Agent Mode: Elisa использует собственные. Прямое подключение к Arena не использует ключ OpenRouter или NVIDIA. Локальные лимиты запросов и токенов настраиваются отдельно, но это не денежный лимит; реальная квота Arena не запрашивается.
- [NVIDIA Build](https://build.nvidia.com/) предоставляет API для тестирования, но наличие моделей, лимиты, цена и условия конфиденциальности могут меняться; не предполагается безлимитная бесплатность. Само подключение не требует установленного Python или видеокарты NVIDIA.
- Для Python установите Python 3 и перезапустите Elisa. В полном режиме `python_run` запускает системный Python (`py -3`, затем `python`) или `.venv` в выбранной рабочей области. Агент может создавать окружение (`python -m venv .venv`), ставить пакеты (`python -m pip install …`), запускать скрипты и тесты; команды, вывод, ошибки и статус показаны в чате. Окружение изолирует зависимости, **не ограничивает доступ к системе или сети**. Без полного режима Python-инструмент выключен. Встроенной установки Python нет; используется установленный пользователем Python.

## Агенты и GitHub

- Оркестратор решает, когда делегировать. На один ход доступны до 4 делегирований; каждый агент получает отдельный контекст с конкретной задачей, вызывает те же доступные инструменты и возвращает результат оркестратору. Агентам недоступно дальнейшее делегирование. Инструмент `delegate_parallel` выполняет одновременно 2–3 независимые задачи исследования/проверки: подагентам доступны только инструменты чтения выбранных рабочих областей и локального поиска. Запись, GitHub, запуск кода и вложенное делегирование блокируются. Это не песочница ОС; фоновой очереди нет. Все вызовы модели и инструментов расходуют лимиты соответствующих сервисов. Карточки делегирования и шаги подагентов видны в чате. Качество планирования зависит от модели и не гарантирует, что она всегда вызовет нужный инструмент.
- Установите [GitHub CLI](https://cli.github.com/) и перезапустите Elisa. В **Настройки → GitHub** нажмите «Войти в GitHub», завершите авторизацию в терминале и браузере и затем проверьте подключение. Elisa использует авторизацию `gh`, не просит вводить токен в чат и не хранит GitHub-токен отдельно. При уже настроенном `gh` может использоваться существующая активная учётная запись. Настройки организаций, SSO, защита веток, права учётной записи и выданные OAuth scopes могут ограничить действия; запрос прав не гарантирует универсального доступа.
- Инструмент `github_cli` доступен и без полного режима Windows, использует `gh` без подтверждений и даёт агентам широкие права GitHub, в том числе на приватные репозитории, слияние и удаление при наличии прав. **Команды gh не ограничены рабочими областями**: они могут читать, изменять и передавать локальные файлы, использовать пользовательские расширения и сетевой доступ. Для обычных команд git (commit/push и т. п.) включите полный режим PowerShell. Не предоставляйте доступ, если такие права неприемлемы.
- При компрометации промпта содержимое репозитория может попытаться повлиять на агента. Результаты GitHub-инструментов отправляются выбранному сервису и провайдеру модели; секреты или приватные данные могут попасть во внешний сервис. Инструкция не читать секреты не является технической защитой. Отменить доступ можно через `gh auth logout` и настройки авторизованных OAuth-приложений GitHub.

## Память, проекты и лимиты

- **Настройки → Память**: вручную добавляйте и удаляйте до 40 заметок по 500 символов. Агент может сохранить заметку инструментом `remember` по просьбе пользователя. Заметки зашифрованы в локальном состоянии и включаются в запросы как контекст, в том числе к подагентам и выбранным провайдерам. Не храните секреты; модель может ошибаться, а инструкция не является технической гарантией.
- Когда история запроса превышает приблизительно 120 000 символов и есть больше двух ходов, для отправки сохраняются три последних полных хода и автоматически выбранные короткие фрагменты старых сообщений. Это **извлекательная заметка, не семантическое резюме**: детали могут теряться. Полная история на диске и в интерфейсе не удаляется. Лимит измеряется символами JSON, а не токенами; большой одиночный ход или маленькое окно модели всё равно могут не поместиться.
- `search_project` и `project_overview` создают временный локальный лексический индекс выбранной рабочей области: максимум 1000 файлов, 4 МБ текстовых данных, 128 КБ на файл. Скрытые папки, `.git`, `node_modules`, `.venv` и имена с `secret`/`credential` пропускаются; это не полноценный .gitignore и не надёжная фильтрация секретов. Индекс не использует embeddings, не сохраняется на диск, ограничен файлами определённых типов и строится заново, поэтому поиск может пропустить результаты. Результаты поиска и манифесты отправляются модели. В полном режиме обзор дополнительно запрашивает локальные `git status` и последние пять коммитов.
- В полном режиме `verify_project` обнаруживает и запускает `npm test`, `pytest` и `dotnet test` для подходящих файлов в корне проекта, если соответствующие инструменты установлены. Запускаются реальные проектные скрипты, которые могут исполнять произвольный код без подтверждения. При записи файла с кодом через `write_file` Elisa также запускает обнаруженные проверки перед финальным ответом и передаёт результат модели для исправления. Изменения через PowerShell, Python или GitHub автоматически не отслеживаются. Показаны команды, вывод и коды; модель может анализировать и исправлять ошибки, но успешность не гарантируется. Нет автоматической установки зависимостей.
- **Настройки → Лимиты** задают отдельные локальные дневные пределы запросов и учтённых токенов (UTC) для каждого провайдера. Ноль означает отсутствие ограничения. Запрос учитывается перед отправкой, включая ошибки; токены — только если сервис вернул `usage`. Предел токенов проверяется до начала запроса и может быть превышен текущим ответом или параллельными запросами; это не лимит стоимости и не учёт других приложений. OpenRouter дополнительно позволяет вручную обновить реальную квоту бесплатных запросов и расходы по API-ключу, если сервис возвращает эти поля. Квоты NVIDIA и Arena не выдумываются. Автоматического переключения на платные модели нет, но вручную выбранная модель может быть платной.

## Поток, диагностика и предпросмотр

- Основной агент показывает поступающий текст ответа по частям, если провайдер поддерживает OpenAI-compatible SSE. Части вызовов инструментов собираются до исполнения; служебные reasoning-блоки сохраняются для продолжения вызовов. Подагенты пока отвечают целиком. Если соединение оборвалось или запрос остановлен, незавершённый текст исчезает и не записывается в контекст; уже выполненные действия не откатываются. Некоторые провайдеры могут не возвращать usage для потока, тогда учёт токенов неполон. Поддержка потока зависит от модели и сервиса.
- **Настройки → Модели → Проверить сохранённую модель** проверяет только выбранную основную модель и сохранённый ключ. Примените изменения перед проверкой. Отправляется до трёх настоящих запросов: текст, пробный вызов безвредного инструмента и крошечное тестовое изображение. Это может расходовать квоту и деньги и учитывается локальным лимитом; если usage не возвращён, токены не учтены. «Не подтверждено» не доказывает отсутствие возможности: причиной могут быть сеть, ключ, квота, модель или формат запроса. Принятие изображения не гарантирует его понимания. Маршруты подагентов отдельно не проверяются, для этого можно временно выбрать нужную модель основной.
- **Предпросмотр HTML** в рабочей области настроек или в чате открывает выбранный `.html`/`.htm` в отдельном окне WebView2, без доступа к привилегированному интерфейсу Elisa и его bridge. Соседние файлы загружаются по относительным ссылкам; серверную часть, сборку проекта и dev-сервер окно не запускает. Открывайте только доверенный HTML: его JavaScript может получать доступ к файлам выбранной папки через виртуальный сайт и обращаться в сеть, в том числе отправлять туда данные. Окно не является полноценной песочницей Windows. Внешние переходы и всплывающие окна блокируются, браузерные разрешения и загрузки отклоняются; ресурсы из сети могут загружаться. Для предпросмотра используется отдельный профиль WebView2 в `%LOCALAPPDATA%\Elisa\PreviewWebView2`, origin каждый раз новый. Не выбирайте папки с секретами.

## Чаты, статистика и локальное хранилище

- Правой кнопкой мыши по чату в списке или карточке можно переименовать или удалить его. Удаление сразу удаляет и историю модели; отмены пока нет. Пока запрос выполняется, изменения чатов заблокированы.
- Справа показаны токены по моделям из поля `usage` ответов провайдера. Учитываются только ответы, где провайдер вернул данные, и только начиная с установки этой версии. Это не история расходов и не статистика баланса. Если фактическая модель не указана в ответе, используется ID запрошенной модели.
- Таймер «Думаю» измеряет ожидание ответа провайдера, включая сеть; это не измерение внутренних рассуждений модели.
- `%LOCALAPPDATA%\Elisa\Storage` создаётся при запуске, с папками `Projects`, `Notes` и `Exports`. Здесь удобно хранить файлы проектов, заметки и результаты. Справа можно открыть хранилище или добавить его в рабочие области, чтобы агент мог работать с его файлами. Содержимое этой папки **не шифруется автоматически**, в отличие от сохранённой истории и API-ключа. Вложения не копируются в неё автоматически.
- Имена файлов в формате inline code и локальные ссылки `file:///` в ответе открываются по нажатию. В режиме рабочих областей поиск ограничен этими папками; в полном режиме допускаются абсолютные пути и имена на рабочем столе. Исполняемые и неизвестные типы не запускаются: вместо этого файл выделяется в Проводнике. Если найдено несколько совпадений, нужен абсолютный путь.

## Ответы и действия агента

Ответы поддерживают Markdown: заголовки, списки, таблицы, ссылки, цитаты и блоки кода с подсветкой и кнопкой копирования. Внешние изображения из ответов не загружаются автоматически. Команды и параметры каждого инструмента показываются до выполнения; затем отображаются статус и результат. Блоки действий свёрнуты по умолчанию; краткое описание и статус видны сразу, а команда и результат раскрываются по нажатию. Действия сохраняются в истории; если приложение закрылось во время выполнения, статус будет «Остановлено» — фактическое состояние команды следует проверить вручную. Скрытые внутренние рассуждения модели не отображаются.

## Вложения и сохранение

- Перетащите файлы в окно или выберите их кнопкой скрепки. Можно прикрепить до 8 файлов: максимум 8 МБ на файл и 12 МБ на сообщение. Отправка возможна и без текста.
- Картинки PNG, JPEG, GIF и WebP показываются в чате и после перезапуска. Агент может прикрепить существующую локальную картинку в чат инструментом `attach_image` (до 8 МБ, в разрешённой области или в полном режиме). SVG и удалённые изображения автоматически не показываются. Это не генератор изображений: создать файл должна модель при помощи доступных ей инструментов.
- Вставка изображения из буфера обмена через Ctrl+V добавляет его к сообщению. Для изображений нужна модель с поддержкой image input. Текст из буфера от 4000 символов автоматически становится вложением `.txt`; он передаётся модели как текст.
- Текстовые файлы передаются как текст; изображения — как `image_url`; PDF и другие бинарные файлы — как file-вложения. Для PDF через OpenRouter выбран парсер Cloudflare AI (текстовый парсер, не полноценный OCR). За токены модели может взиматься плата. Поддержка файлов зависит от модели и сервиса: произвольные бинарные форматы могут быть отклонены, даже если их можно прикрепить в интерфейсе.
- Чаты, контекст модели (включая отправленные вложения), ID моделей и API-ключи сохраняются в `%LOCALAPPDATA%\Elisa\viora-state.dat`, зашифрованном через Windows DPAPI для текущего пользователя. Доступен другим процессам той же учётной записи; это не защита от вредоносного ПО. При переносе на другой ПК или учётную запись файл может не расшифроваться. Если файл невозможно прочитать, Elisa не перезапишет его автоматически и предупредит пользователя.
- Сохраняются имена вложений и растровые предпросмотры; байты вложений сохраняются в контексте модели после успешного хода. При ошибке незавершённый ход не попадает в контекст. Чаты можно удалить через контекстное меню; удаление ключа отдельно пока не реализовано; для удаления всех сохранённых данных закройте приложение и удалите `viora-state.dat`.

## Безопасность и ограничения

- Автоматические действия могут испортить или удалить данные. Настраивайте рабочие области в папках без секретов и используйте резервные копии. При полном доступе команды могут затронуть любые доступные папки и сеть.
- Ограничение рабочих областей — проверки путей в файловых инструментах, **не песочница Windows и не защита от вредоносных локальных процессов**. Символические ссылки и junction/reparse points в путях запрещены, но возможны гонки и жёсткие ссылки. В полном режиме PowerShell все ограничения папок обходятся по определению.
- Содержимое файлов и результаты инструментов отправляются выбранному сервису и провайдеру модели. Не вводите секреты в чат. Ключ и история сохраняются локально в зашифрованном виде. Список рабочих областей и переключатель полного доступа сохраняются в `%LOCALAPPDATA%\Elisa\workspaces.json`.
- Максимум 32 вызова инструментов и 4 делегирования на ход (общие для всех агентов), 90 секунд на команду GitHub CLI, 120 секунд на процесс Python, 60 секунд на команду PowerShell, 24 000 символов вывода на поток. Файловые инструменты работают только с UTF-8 файлами до 1 МБ; вывод модели ограничен. Остановка не откатывает изменения, а отделённые процессы могут продолжить работу.
- При ошибке или остановке незавершённый ход не сохраняется в контексте модели; сообщите модели, какие действия уже были выполнены.

## Сборка EXE в Windows

Установите [.NET 8 SDK](https://dotnet.microsoft.com/download/dotnet/8.0) и [Node.js](https://nodejs.org/) 20.19+ или 22.12+ с npm. Нужен интернет для npm и NuGet. Запустите `build.bat` или выполните в PowerShell из папки проекта:

```powershell
.\build.bat
```

Готовый файл — `build\Elisa\Elisa.exe`. Копируйте **всю папку `build\Elisa`**, включая `wwwroot`. Сборка включает .NET Runtime; для запуска нужен [Microsoft Edge WebView2 Runtime](https://developer.microsoft.com/microsoft-edge/webview2/) (обычно установлен в Windows 11).

Для разработки интерфейса выполните `npm install` и `npm run dev`. В браузере доступен только просмотр интерфейса: агент и ключ работают исключительно в Windows-приложении.

## Сборка на GitHub

При каждом push GitHub Actions собирает приложение на Windows. Откройте **Actions**, выберите запуск **Build Elisa for Windows** и скачайте артефакт `Elisa-Windows-x64`. Распакуйте его целиком и запустите `Elisa.exe`.
